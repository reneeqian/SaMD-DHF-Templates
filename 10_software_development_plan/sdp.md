## 1. Purpose and Scope

This Software Development Plan (SDP) defines the lifecycle processes, tools, standards,

## 2. Lifecycle Model

This project follows an iterative development lifecycle:

| Phase | Description | Key Outputs |
|---|---|---|
| Requirements | Define and review software requirements | `docs/requirements.yaml` |
| Architecture | Design component structure and interfaces | `03_architecture/` |
| Implementation | Code + unit tests; TDD approach | Source code + test suite |
| Verification | Automated V&V; evidence generation | `artifacts/evidence_runs/` |
| Release | Tag, baseline, and update DHF | git tag, `baseline_register.md` |
| Maintenance | Monitor, patch, and document changes | `11_anomaly_log/`, `change_log.md` |

## 6. Requirements Management

Requirements are authored in `docs/requirements.yaml` using domain-prefixed IDs per
`requirements_convention.md`. All new functionality requires a documented requirement
before implementation begins. Requirements are traced to tests via
`@pytest.mark.requirement("DOMAIN-NNN")` markers; traceability is auto-generated by
`python runtests.py`.

## 7. Configuration Management

See `07_configuration_management/cm_plan.md` for the full CM plan, including branching
strategy, release tagging policy, and baseline register.

## 8. Problem Resolution

All anomalies (defects, unexpected behaviors, test failures) are recorded in
`11_anomaly_log/anomaly_log.md` per IEC 62304 §9. Intentional changes are recorded in
`09_change_control/change_log.md`.

## 9. Verification Approach

See `06_verification/verification_plan.md` for the full verification plan.

Minimum acceptance criteria before any release:
- All tests pass (100% pass rate)
- Requirements coverage: 100%
- forge health grade: ≥ B
- pip-audit: 0 high or critical CVEs
